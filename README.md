任务一

用两块 STM32F103C8T6 最小系统板模拟 RM 步兵「云台板 + 底盘板」的控制链路。双板通过 CAN 通信，云台板负责摇杆采集与舵机控制，底盘板负责电机速度闭环与 OLED 显示，两板共用同一工程，通过条件编译区分。

## 1. 系统架构

云台板接收摇杆输入，控制 360 度舵机作为云台 yaw 轴，并通过 CAN 将电机目标速度下发给底盘板。底盘板接收目标速度，驱动减速电机完成速度闭环，并回传实际转速。板载 LED 作为状态指示，云台板在 CAN 通信异常时呼吸灯闪烁，底盘板在电机异常时呼吸灯闪烁。

## 2. 代码分层

工程分为硬件层、中间层和应用层。
硬件层在 bsp 目录，封装各外设驱动，包括 CAN、舵机、电机、摇杆、LED、OLED。
中间层在 component 目录，提供 PID、斜坡、滤波等算法。应用层在 application 目录，实现云台板、底盘板、CAN 收发和 OLED 显示逻辑。
Core 目录存放 CubeMX 生成的 HAL 初始化代码。

## 3. FreeRTOS 任务设计

工程使用 FreeRTOS，共四个任务。
startTask 在启动后按板型删除本板不需要的任务，然后自删除。
gimbalTask 周期 5ms，负责云台板读取摇杆、控制舵机、下发 CAN 并刷新 OLED。
chassisTask 周期 5ms，负责底盘板测速、速度环 PID 控制、驱动电机并回传 CAN。
oledTask 周期 50ms，负责底盘板刷新 OLED。

## 4. 板间通信方案

两板共用一条CAN 总线，使用标准帧。
云台板发送 0x110 帧，前两个字节是目标电机速度，后两个字节是目标舵机速度。
底盘板发送 0x113 帧，前两个字节是实际电机转速，第三个字节是电机在线标志。
双方通过心跳机制判定对方在线，接收方记录最近收到帧的时间，超过 100ms 视为离线。
上电后收到第一帧才判定在线，避免误判。
滤波器只接收 0x110 到 0x11F 区间的帧，存入 FIFO1，在接收中断中按 ID 分发。

## 5. 所用算法

速度环使用位置式 PID，误差为目标转速减实际转速，输出映射为 PWM 占空比和方向，带积分限幅和输出限幅防止积分饱和。
目标转速经过斜坡函数平滑逼近，避免阶跃冲击，实现平稳运转。
编码器测速结果经过一阶低通滤波，抑制量化噪声。
另外有堵转检测，当目标转速较高而实际转速长期接近 0 时判定电机异常，停机并触发呼吸灯。

## 6. 双板条件编译

在 application/board_config.h 中设置板型。编译云台板时将 BOARD_GIMBAL 置 1，编译底盘板时将 BOARD_CHASSIS 置 1，另一块置 0。同一工程编译两次得到两块板的固件。
